# Skill: Direct Successor Autopilot

Use this skill after current-state authentication and Artifact Compass classification when choosing or executing the next bounded release.

The purpose is to prevent random feature expansion while still moving automatically through reversible engineering work.

## First action

Run a whole-system reality audit:

- repository truth;
- runtime truth;
- verified capabilities;
- current gaps;
- tests/evidence;
- protected authority;
- current hardware/runtime constraints.

Then use Artifact Compass to research only the technologies relevant to the current missing capability.

## Select one direct successor

A direct successor must:

- close one real owner-visible or kernel-contract gap;
- preserve verified capabilities;
- fit current hardware/cost/privacy boundaries;
- be testable in isolation;
- have an exact completion gate;
- avoid unnecessary platform/framework migration.

## Autopilot behavior

Continue automatically through reversible candidate work:

- inspect;
- implement;
- test;
- fix ordinary defects;
- rerun affected tests;
- run full relevant suite;
- benchmark where useful;
- create evidence/manifests;
- simulate rollback;
- clean disposable state;
- update restart packet.

Do not ask the owner for routine `continue`, `test it`, `fix it`, `make rollback`, or `make manifest` approvals.

## Stop only at a real gate

Stop before:

- modifying the authoritative local Workshop;
- live deployment;
- destructive permanent data changes;
- external publishing;
- spending/enabling paid services;
- widening credentials or persistent permissions;
- any owner-defined protected gate.

## Completion report

Report:

- exact capability now proven;
- exact remaining gaps;
- tests/evidence;
- changed-file scope;
- dependency/runtime/provider/database status;
- protected-state verification;
- rollback result;
- hashes/manifests where applicable;
- exact owner approval string only if a live gate is next.

Codex owns engineering proof. The owner owns product truth and deployment approval.
